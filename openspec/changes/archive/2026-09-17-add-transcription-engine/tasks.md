## 3. Engine core

- [x] 3.1 Add the native seam `INativeSpeechEngineFactory` / `INativeSpeechEngine` and the production adapter over TranscribeCppSharp `Backends`, `Model` and `Session` (load with backend, run with task and languages and a cancellation token, `MaxAudio` from `GetLimits`, dispose session before model; for `transcribe`, pass the source language as the target language; on `ErrOutputTruncated`, return `session.FullText` with a truncated flag). Verify: builds. Behavior is covered by the hardware tests in 5.x.
- [x] 3.2 Implement `TranscribeCppTranscriber`: status state machine and `StatusChanged`; a single LongRunning worker over a FIFO `Channel`; `LoadAsync`, valid in `NotLoaded` and `Failed`, with warm-up (D5); `TranscribeAsync` with the not-ready check, validation, empty-input short-circuit and max-duration check before enqueueing. Verify: unit tests with a fake seam cover the status sequence NotLoaded→Loading→Ready, `LoadAsync` from `Failed` → Ready, `LoadAsync` while Loading or Ready → `InvalidOperationException`, rejection while Loading, empty input never reaching the seam, 401 s rejected when the max is 400 s, and two overlapping requests executing sequentially in FIFO order (the fake records the call order and asserts no overlap).
- [x] 3.3 Implement backend selection and fallback with the status-code classes from design D4 (Auto: Vulkan if available, fall back to CPU on a backend failure during load or warm-up with the reason logged; Vulkan: no fallback; CPU only). Verify: unit tests cover Auto with a Vulkan load failure → Ready(CPU), Auto with a Vulkan warm-up failure → Ready(CPU), Vulkan unavailable → CPU, forced Vulkan failure → Failed with no CPU attempt, forced CPU never touching Vulkan, Auto with `ErrGguf` on Vulkan → no CPU attempt, and a warm-up returning `ErrOutputTruncated` → Ready(Vulkan).
- [x] 3.4 Implement damaged-model handling (on an invalid-model load failure, hash the file; on a mismatch delete it and notify re-download; on a match keep it and notify incompatible). Verify: unit tests with temp files and a fake seam cover both branches, including the file being deleted or kept and the notification text.
- [x] 3.5 Implement shutdown (cancel the in-flight run, wait ≤ 3 s; only the worker disposes, after its native call returned; skip disposal if the worker is still busy). Verify: a unit test with a fake run that blocks until cancelled confirms `StopAsync` completes within 3.5 s, and a fake run that ignores cancellation confirms `StopAsync` returns after about 3 s without disposing while the run is still blocked.
- [x] 3.6 Implement errors during a run (design D10). Verify: unit tests with a fake seam cover Auto on Vulkan with a backend error → the request fails with `TranscriptionFailedException`, the status goes Loading → Ready(CPU), and a request queued behind it completes on CPU; forced Vulkan with a backend error → Failed with the model disposed; a backend error on CPU → Failed; truncated output → partial text returned and status Ready; another error → `TranscriptionFailedException` and status Ready.
- [x] 3.7 Use the backend-specific warm-up input from D5 (Vulkan: 10 s of fixed pseudo-random noise in [-0.1, 0.1]; CPU: 1 s of silence), also in the benchmark test. Verify: unit tests with the fake seam check the warm-up input on Vulkan, on CPU, and on the CPU reload after a Vulkan failure; rerun the benchmark on the target laptop and update the warm-up column in `notes.md`.
